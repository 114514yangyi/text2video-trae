这一页是本次组会汇报的封面，主题是从德语文本直接生成手语视频。整个方法建立在两个前提上：一是冻结的 VAE 把每一帧画面压成一个 1024 维的 token，二是扩散过程在这个 latent 空间里进行，全程没有 pose 中介、也没有 pose 监督，条件只来自文本。左下角的数字是当前表现最好的实验 prefix_120k 的结果：在单侧测试集上 BLEU-4 是 3.18，BLEU-1 是 12.55，ROUGE-L 是 12.60，WER 是 100.5，检索指标 MRR 是 0.0336，也就是零信息地板的 3.06 倍。下面这条真实视频抽帧来自 PHOENIX14T，用来说明我们要生成的对象长什么样。本期汇报按四段展开：模型架构、模型表现、生成与真实视频对比，以及我们目前遇到的困难点。

## 03 课题与方法硬约束

**页面内容**

- **任务**：德语文本 → 手语视频（RWTH-PHOENIX-Weather 2014T）
- **数据**：可用训练片段 7021 条（max_num_frames=256 过滤后）；平均句长约 110 帧
- **硬约束①**：冻结 VAE —— 生成必须基于已训练好的 1-token（每帧 1024 维）VAE，不换 tokenizer
- **硬约束②**：潜空间扩散 —— 扩散在 VAE latent 空间进行，不回到像素态
- **硬约束③**：x-prediction —— 网络预测干净 latent x0，噪声或速度只作等价换算
- **硬约束④**：纯文本条件 —— 条件只能来自文本；部署所需长度也由文本预测，VAE 解码锚点属冻结 VAE 固有输入

**口播稿**

这一页交代任务定义和四条必须同时成立的方法硬约束。任务是德语文本到 RWTH-PHOENIX-Weather 2014T 手语视频，按每一段不超过 256 帧过滤之后，可用训练片段只有 7021 条，平均句长大约 110 帧，数据规模是偏小的。第一条硬约束是生成必须基于已经训练好的 1-token VAE，每一帧压成 1024 维，不能更换 tokenizer。第二条是扩散必须在 VAE 的 latent 空间里做，不能回到像素空间。第三条是必须使用 x-prediction，也就是网络直接预测干净的 latent。第四条是纯文本条件，不能引入 pose、参考帧或光流等额外监督；部署时需要的视频长度也由文本预测，真实视频的第一帧只是冻结 VAE 解码时本来就需要的锚点，不算新增条件。

## 04 三段式数据流与总体架构

**页面内容**

- **① 冻结 VAE**：与 ../RefSign 共用 TiTok-CVAE；每帧 → 1 token × 1024 维；缓存 phoenix_latents/v1 只读软链；sha256 强制校验
- **② DiT-B 主干**：可训练，约 1.82 亿参数；噪声 latent（T × 1024）→ 预测干净 latent x0；hidden 768 / depth 12 / heads 12
- **③ 解码**：冻结 VAE 解码器；干净 latent + GT 首帧（CVAE 解码锚点）→ 还原 256×256 视频
- **条件支路**：mT5-base（max_length=120）→ 池化向量 + 前缀 token；长度由文本预测（8 桶 + expectation 回读）→ log 归一化进入 adaLN
- **图例**：灰 = 冻结；蓝 = 可训练

**口播稿**

这一页是三段式数据流的整体架构图，横向从左到右看。第一段是冻结的 VAE，与相邻项目共用的同一条 TiTok-CVAE，把每一帧压缩成一个 1024 维 token，latent 缓存是只读的，训练进程本身不加载 VAE。第二段是 DiT-B 主干，这是整条链路里唯一可训练的部分，输入是加了噪声的 latent，输出是它预测的干净 latent，参数量约 1.82 亿。第三段是解码，把干净的 latent 配上真实视频的第一帧作为解码锚点，还原成 256 乘 256 的视频。下面这一行是条件支路，条件只来自文本：mT5 编码器把句子编码成池化向量和前缀 token，句子长度由文本预测，做 log 归一化之后和文本向量一起送进主干。图例里灰色表示冻结模块，蓝色表示可训练模块。

## 05 DiT-B 主干与 text-prefix 联合注意力

**页面内容**

- **规格**：hidden 768 / depth 12 / heads 12 / mlp_ratio 4.0 / 约 1.82 亿参数
- **官方结构保留**：adaLN-Zero block · c = t_emb + y_emb · sincos 位置编码 · FinalLayer 零初始化
- **为 1 token/帧的改动**：PatchEmbed → Linear(1024, hidden) · 1D sincos · 文本/长度条件 · cross-attention 变体 · frame_mask
- **text-prefix**：文本 token 作为前缀拼进 self-attention，带可学习 type embedding；cross-attention 同时保留
- **动机**：通道探针：cross-attn 输出对文本反应很强，但被零门控压到只让 block 输出动约 5%、模型输出动约 1%
- **扩散配方**：prediction_type = x0 · noise_schedule = cosine · timestep_sampling = logit_normal；评测 DPM-Solver++(2M) 50 NFE · CFG 2.0

**口播稿**

这一页讲主干内部，以及本实验最关键的那一处改动。规格上严格对齐官方 DiT 实现：隐藏维 768，深度 12 层，注意力头 12 个，mlp_ratio 是 4.0，训练参数约 1.82 亿。为了适配每帧只有一个 token 的输入，代码里做了几处改动：把 patch embedding 换成从 1024 维到隐藏维的线性层，把二维位置编码换成一维、沿帧轴排布，类别标签条件换成文本和长度条件，另外保留论文附录里的 cross-attention 变体，以及处理变长视频的 mask。关键的改动是 text-prefix：把文本 token 当作前缀，和潜码帧 token 拼成一条序列一起送进自注意力，用的是 mmDiT 和 SD3 的思路，同时保留原来的 cross-attention。动机来自一次通道探针：cross-attention 的输出对文本反应很强，但被零门控压得几乎传不出去，只剩下大约百分之五的扰动，所以直接给文本一条自注意力通道是最便宜的加强方式。采样配方上，预测目标是干净 latent，噪声调度是 cosine，时间步采样是 logit-normal，评测用 DPM-Solver++ 五十步，CFG 是 2.0。

- **评测口径**：DPM-Solver++(2M) 50 NFE · CFG 2.0 · oracle 长度；predicted-length 列验证部署闭环（三项指标无显著差异）

**口播稿**

这一页交代训练配方和当前最好实验是怎么来的。超参是一组并列事实：batch 16，AdamW 学习率 1e-4，权重衰减为零，EMA 是 0.9999，bf16 混合精度，梯度裁剪 1.0，单卡训练。训练预算沿革这条时间轴是从 30k 步到 60k、90k、120k，配方一直没变，只是不断加步数。来源链路是：先从 30k 基线的配置训到 60k 存档，再用这个存档作为初始权重继续训 6 万步，得到 runs/prefix_120k/final.pt。这样安排的意义在于，它构成了后面的对照基础——加预算有效，而不是靠改机制。评测口径是 DPM-Solver++ 五十步、CFG 2.0、oracle 长度，另外还有一列用预测长度来验证部署闭环，三项指标没有显著差异。

## 09 回译举例：语言对了，动作还不对

**页面内容**

- **①**：参考 aber erfreuliche nachricht → 生成回译 im ganzen land.
- **②**：参考 es scheint häufig die sonne → 生成回译 und das ist jetzt auch der fall für uns alle.
- **③**：参考 am sonntag ab und an regenschauer teilweise auch gewitter → 生成回译 am freitag regnet es dann im ganzen land.
- **读法**：生成视频被 SignMbart 读成通顺但内容不对的天气预报句子；模型学到了语言分布，没学到对应的手势动作（N=642 实测条目）

**口播稿**

这一页用三条真实条目解释"通顺但不对"是什么意思。做法是把生成出来的视频交给 SignMbart 回译成德语，再看它读出了什么。第一条参考文本是 aber erfreuliche nachricht，生成视频被读成 im ganzen land。第二条参考 es scheint häufig die sonne，被读成 und das ist jetzt auch der fall für uns alle。第三条参考 am sonntag ab und an regenschauer teilweise auch gewitter，被读成 am freitag regnet es dann im ganzen land。可以看到，回译出来的都是语法正确、语义通顺的德语天气预报句子，但内容跟原句对不上，星期、天气状态经常被替换成别的词。这说明模型学到了德语天气预报的语言分布，却没有学到这段文本对应的具体手势动作。

## 12 当前困难点

**页面内容**

- **① 动作语义**：BLEU-4 3.18，对冻结 VAE 重建 14.93、真视频 29.51；回译通顺但内容不对
- **② 已饱和轴**：累计九条机制类改动全部零收益或显著为负；正向结论只剩文本分支 lr 5e-5 与加预算
- **③ 检索**：MRR 0.0336 = 零信息地板 0.0110 的 3.06×，top-1 只有 1.09%
- **④ 容量与数据**：同步数加宽 / 加深都更差（B1 −1.48 / −1.12）；可用训练片段只有 7021 条
- **⑤ 冻结 VAE 上限**：每帧 1 token × 1024 维，手部细节在重建阶段已损失；硬约束禁止换 tokenizer
- **⑥ 评测栈**：FVD 跨 N 不可比、多 seed 配对检验未完成、长度预测 MAE ≈ 16 帧
- **⑦ 算力与存储**：共享集群不抢占别人作业；输出盘可用 <12 GiB 时暂停起新作业，评测帧跑完即删

**口播稿**

这一页集中讲当前遇到的困难，一共七条。第一，也是最主要的，是动作语义：BLEU-4 只有 3.18，而冻结 VAE 重建上限是 14.93，真实视频是 29.51，回译通顺但内容不对，这不是评分口径的问题。第二，改"条件使用方式"这条轴已经饱和：到目前累计九条机制类改动，包括双流、文本压力课程、表示对齐、多尺度损失、self-conditioning、条件 margin、软时序对齐、保义改写增强和固定槽接口，全部零收益或显著为负；能复用的正向结论只剩文本分支学习率调到 5e-5 和增加训练预算。第三，检索能力的绝对水平仍然很低，MRR 0.0336 虽然是地板的 3.06 倍，但 top-1 只有百分之一点零九。第四，加容量不是解法：同样 30k 步下加宽或加深都明显更差，说明还没到容量饱和，是先欠训练，而可用数据只有 7021 条。第五，冻结 VAE 的表示上限是接受的代价，每帧一个 token，手部细节在重建阶段就已经丢了。第六，评测栈还有没收口的地方：FVD 跨 N 不可比、部署预算点的多随机种子配对检验还没做完、长度预测平均误差大约 16 帧。第七，算力和存储有约束：共享集群上不抢占别人的作业，输出盘剩余不足 12 GiB 时会暂停起新作业，评测帧跑完就删。
