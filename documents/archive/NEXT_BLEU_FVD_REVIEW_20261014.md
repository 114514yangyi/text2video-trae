# NEXT_BLEU_FVD 计划审阅与修订建议

日期：2026-10-14。对象：`.trae/documents/archive/NEXT_BLEU_FVD_EXPERIMENTS_20261013.md`（下称"计划"）。
本轮做了三件计划里没有的事：给指标定标（无信息地板 / 表示上限）、补视频侧对照、
把 latent 检索做成可用的高分辨力指标。结论与该计划的部分前提相反，故单独立档。

## 0. 结论摘要

1. **该指标的地板是 B1≈9.3；现役 prefix-60k 生成是 9.47。** 把一条完全无关的真视频
   配到同一句参考文本上，SignMbart 给出 B1 9.32 / ROUGE 9.22 / B4 0，与现役生成
   （9.47 / 9.57 / 0）在配对 bootstrap 噪声内相同。**当前部署模型在该指标下与
   "视频不含这句话的信息"不可区分。** 计划中所有 ±0.5~1 B1 的晋级判据都在噪声里。
2. **表示层不是主瓶颈，条件生成才是。** 冻结 1-token VAE 用真实 latent 重建后
   回译 B1 31.57 / B4 14.93 / ROUGE 29.32 / FVD 28.37（PSNR 26.4 dB），
   而现役生成是 9.47 / 0 / 9.57 / 51.61。1-token 表示自身丢掉约 19 B1（50.4→31.6），
   但 DiT 又丢掉了 22 B1（31.6→9.5）。继续在语义 loss 权重上做 0.5 B1 级别的微调，
   与"先让模型脱离地板"相比优先级过低。
3. ~~**"继续训练有没有用"这个问题，答案倾向"有"。**~~ **（2026-10-14 傍晚推翻，见 §8.7）**
   原文依据是 prefix-90k 在 32 条 test、DDIM 50 下全面优于 60k，以及对"错配真视频"的正向。
   在 64 条 dev、DPM++ 50 下重做配对 bootstrap：**90k 的 BLEU-1 显著更低**
   （ΔB1 −3.69，95% CI [−6.64, −0.58]，P(>0)=0.01），ROUGE 也更低（P=0.08），
   只有检索 MRR 与 WER 偏向 90k。**旧的"90k 无额外收益"结论在 BLEU 口径下是对的；
   本条不能作为"继续训练有益"的依据，必须按 §8.7 先解决指标互相矛盾的问题。**
4. **原筛选协议欠采样（已确认），但采样预算不是全部原因（2026-10-14 下午补齐阶梯）。**
   prefix-60k 同 checkpoint、同 32 条 test：DDIM 50 → B1 9.47 / B4 0.00 / FVD 51.61；
   100 → 9.17 / 0.00 / 51.42；**250 → 10.88 / 2.77 / 51.39**；**500 → 9.23 / 2.59 / 51.27**。
   B4 从 0 跳到 2.6–2.8 后不再增长，B1 在 9.2–10.9 之间来回（n=32 时 B1 的噪声就有 ±3）。
   结论分两层：(a) 用 50 步做筛选确实把 B4 压在地板上，**所有 50 步的 B4 比较必须作废**；
   (b) 但把步数加到 500 只买到 B4 ≈ 2.7，离冻结 VAE 上限 14.93 还差 12 个点——
   **剩余差距不是采样造成的**，是条件利用率/模型能力问题。§7 给出更省算力的替代：换二阶求解器。
5. **需要换主指标（用户 2026-10-14 已同意）。** 用独立 latent→文本教师做检索
   （`tools/probe_latent_retrieval.py`），MRR 在真实重建上 0.246、prefix-90k 0.218、
   prefix-60k 0.135，随机水平 0.127（N=32）。它比 BLEU 的分辨力高一个量级，且不经过
   冻结的 SignMbart 语言先验。**B4 在 n=32 上不可用于比较**：本轮 DPM++ 20/50/100 步给出
   B4 = 2.02/0.00/0.00，而 MRR = 0.137/0.153/0.160 单调，说明 B4 的 0↔2.8 抖动是
   4-gram 计数太小，不是模型差异。筛选口径：MRR + ROUGE + WER + FVD，B4 仅作汇报。

## 1. 计划漏洞（按严重度）

### H1 致命：没有先给指标定标，7 条路线都建立在分辨力不足的指标上
计划把"VAE 重建参考"列为 P1 诊断之一，但没设判据、也没把它放在筛选之前。
实测已证明：**地板 9.3 与现役 9.5 重合**，因此 E1（λ 消融）、E3（逐词教师）
以及历史上的 30k/60k/90k 比较，都是在"地板附近"比较两个都接近无信息的模型。
修正：任何新模型必须先报"相对地板/上限的位置"，再谈 BLEU 提升。

### H2 严重：筛选预算与判据不匹配（统计功效不足）
- 32 条配对 bootstrap 的 95% CI 约 ±3 B1（`runs/preferred_route/paired_*.log`）。
- 计划里的晋级线是 +0.5~1 B1，E1 的 λ 差异（12.14 vs 11.52）远小于 CI。
- 单次训练、单生成 seed、无重复，训练 seed 方差从未估计。
修正：筛选集从 64 dev 扩到全 518 dev；固定 3 个生成 seed；全部比较用配对
（同初始噪声、同长度、同文本）；主指标换检索 MRR（见 §3 T0）。

### H3 严重：5k 筛选预算与 60k/90k 部署预算之间的"排序保持假设"未验证
计划所有单因素实验都是 5k；而已知最大单个效应是预算本身
（prefix 30k 6.72 → 60k 9.47 → 90k 14.75）。若方法排序随预算翻转，整套筛选结论作废。
修正：拿 2 个候选方法做 {5k, 20k} 的 rank-preservation 检查（约 2 GPU 小时），
通过后才允许用 5k 做筛选。

### H4 严重：口径分裂，跨线结论不可比
prefix 线用 32 条 **test**（带 padding 长度），A/B/C 线用 64 条 **dev**（oracle 长度）；
README/NOTES 还残留 GFSLT 口径的表。计划没有先统一评测矩阵，导致
"90k 不如 60k"（GFSLT 口径）与 SignMbart 表（90k 全面更好）并存。
修正：先固化一套评测矩阵（`tools/eval_suite.py`，审计 P1 已提），旧数字标注口径。

### H5 中等：表示上限被当成"可选诊断"，没有预设阈值判据
现在有了数字（31.57 B1 / 28.37 FVD），但它同时暴露新问题：
真实 latent 到重建就损失 19 B1，需要单独归因（256 分辨率、1 token/帧、
运动细节、解码锚点）。计划没有把这条拆成可执行的子诊断。

### H6 中等：只有文本侧对照，没有视频侧对照
"正确 vs 打乱文本"证明模型用了文本，不能证明生成视频与该句对应。
本轮补的错配真视频对照（B1 9.32）给出了必要的地板。

### H7 中等：E1–E7 是并列清单，缺少主因排序与自动切换
现有证据都指向"条件利用率低"（通道探针、文本交换只动 ~1% 输出）。
E1 已执行且收益平淡（λ .01/.02 ≈ λ .05，λ .005 更差），E3 也不如等预算 A-only
（10.99/1.91 vs 11.65/2.16）。计划有停止规则，但缺少"E1/E3 无增量即转 E5/E6"
的显式切换与预算上限。

### H8 中等：长度头质量没有进入指标路径
oracle 长度下 B4 已经常为 0，预测长度下 B1 12.88 / B4 0；长度头 MAE 18 帧、
bucket acc 0.41，在 27–241 帧分布上是纯损失项，且与 DiT 质量无关。
计划把它当作部署细节，实际上它现在是部署口径的主要扣分点。

### H9 中等：语义目标的可达上界没测
用教师 NLL 衡量：真实重建 latent 上 correct−other 的 gap 是 0.675，
生成 latent 上只有 0.10–0.47。这提示"先修生成器"而不是"继续加语义权重"。
计划没有把该 gap 作为语义 loss 的标尺。

### H10 中等：事实上仍在用 SignMbart（且部分在 test）做选点
计划声明"不用 SignMbart 训练/挑选单条样本"，但 E1–E7 的晋级判据全部是
BT 的 BLEU-4 与 FD。审计 M1 已指出部署选择建立在 32 条 test 上，本轮审阅确认
该问题在计划层面没有闭环。

### H11 轻微：方差来源没有分解
训练 seed / 生成 seed / 评测集 / 评测器四类方差混在一起。没有 seed 重复，
无法区分"方法有效"与"这一颗种子运气好"。

### H13 严重（新发现）：筛选协议欠采样，且没有饱和性检查
DDIM 50/100/250 在 prefix-60k 上给出 B4 = 0.00 / 0.00 / 2.77。计划把 B4 当主判据，
却把采样固定在一个 B4 恒为 0 的预算上，等于用一个地板化的指标做筛选。
修正：先做 NFE 阶梯（50/100/250/500）**+ 二阶求解器**，确定"指标饱和点"，
之后所有比较固定在该点之上；已经跑过的 5k 分支必须在饱和预算下复评，否则结论不成立。
（阶梯与求解器都已完成，见 §7.1/§7.2；A5k / A-only / B λ=.05 / λ=.01 / C 的 dev-64、250 步
复评：A5k 与 A-only 已完成，B/C 在跑。）

### H14 中等（新发现）：解码锚点是 GT 首帧，所有数字里都有 oracle 信息
冻结 CVAE 是条件 VAE，解码必须喂 GT 首帧（`configs/*.yaml`：
`feature_dim: 512  # decode anchor (GT frame 0) at decode time`）。因此每条"生成"指标的
前 1/36–1/150 帧是真实帧，且整段解码都受这个真锚点引导；表里从未标注这一点。
本轮补的控制（§8.1）显示这条不是空话：把同一个视频的 latent 换成"第 0 帧重复整段"
（无任何运动），正确文本下 SignMbart 仍给 **BLEU-1 7.55 / ROUGE-L 8.17**，而现役
prefix-60k 生成是 9.47 / 9.57。**该模型只比"一张静止的真实首帧"高约 1.9 B1。**
修正：所有结果表标注 "oracle-anchored"，并把静态帧控制作为第二地板与错配真视频地板并列。

### H15 中等（新发现，机制已证实但改动无收益）：文本前缀 88% 的 key 是 padding，而且全部参与注意力
文本适配器把每句都 pad 到 `conditioning.text.max_length=120`（PHOENIX 德语句实际
20–35 个 token），text-prefix 路径又把这段前缀拼到 latent token 前面，并且
`t2v/models/dit.py` 里原来用 `torch.ones(batch, prefix_len)` 把这 120 个位置**全部**
标成有效 key（`context_mask` 只在 cross-attention 里用）。
`tools/probe_prefix_attention.py` 实测（final_60k.pt，8 句 eval，逐 block 平均）：

| latent query 的注意力质量落点 | 真实词 token(≈23) | pad token(≈97) | latent token |
| --- | ---: | ---: | ---: |
| 全部 12 层平均 | **12.1%** | **40.2%** | 47.7% |
| 最后一层 | 14.6% | 62.9% | 22.5% |

pad 位置在 mT5 里只能被 pad 自己"看到"（T5 的 mask 只屏蔽 key），所以它们是
"每句各不相同、但位置固定、彼此高度相似"的向量（两句 pad 块余弦 0.54、位置间 std 0.07）。
结果就是：模型读到的 4/5 是同一类无语义的 pad 摘要，词级 token 只占 1/8 的质量——
这与"换文本只动 ~1% 输出""语义 loss 只学到主题、B4 恒为 0"的既有诊断完全一致。
修正（已实现、已测、已开训练）：
- `model.mask_text_padding: true`：用 `context_mask` 屏蔽 pad key；
- `model.truncate_text_prefix: true`（必须与上一项同开）：把前缀截到 batch 内最长真句，
  顺带省掉约 1/4 的自注意力算力（376 → ~292 token）；
- 测试 `tests/test_text_pad_mask.py`：默认路径对 pad 内容敏感（证明机制真实存在）、
  开 flag 后输出对 pad 内容**逐位不变**、截断与屏蔽等价；
- 实验：`runs/route_d_padmask_5k`（prefix-60k + 5k，开两个 flag）与
  `runs/route_d_control_5k`（同起点同预算、不开）配对。

**结果（dev-64、DPM++ 2M 50 步、oracle 长度、CFG 2.0、同种子）——假设被证伪：**

| 分支 | BLEU-1 | BLEU-4 | ROUGE-L | WER↓ | FD↓ | 检索 MRR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| route_d_control_5k（无屏蔽） | **10.04** | **2.77** | **10.78** | 100.2 | 45.33 | 0.1077 |
| route_d_padmask_5k（屏蔽 + 截断） | 8.75 | 1.69 | 9.87 | **99.1** | **44.20** | 0.1079 |
| 起点 prefix-60k（同口径） | 11.15 | 1.94 | 10.92 | 108.7 | 41.53 | 0.1121 |

三点读法：(a) 这个"88% padding"病理**实测存在**（注意力质量、pad 内容改变输出都能复现），
但**屏蔽它不提升任何指标**：MRR 0.1079 vs 0.1077 完全持平，BLEU/ROUGE 反而更低，
只有 WER/FVD 略好；(b) 说明模型确实把 pad 摘要当成一条有用的"整体语境"通道在用，
不是纯粹浪费；(c) 两个 5k 分支都没有超过起点 prefix-60k（10.04/8.75 vs 11.15），
说明"从 60k 再纯微调 5k"本身就不是增益方向——这与 H3"预算效应可能压过方法效应"一致。
因此 H15 的严重度下调为**观察**：不再作为提指标的主线，只保留 mask/truncate 作为省算力选项
（前缀 376→~292 token）。**这是本轮唯一一个被等预算对照明确证伪的假设，记录下来防止重复投入。**

| 原始 GT 视频（真视频直接回译） | 50.42 | 29.51 | 48.93 | 61.1 | — | — |
| 冻结 VAE 重建（真实 latent 解码） | 31.57 | 14.93 | 29.32 | 91.8 | 28.37 | 0.246 |

| 错配真视频对照（地板） | 9.32 | 0.00 | 9.22 | 121.0 | — | — |
| 随机水平（N=32） | — | — | — | — | — | 0.127 |

  这同时说明：**90k 不该因为旧 GFSLT 口径被 60k 顶掉**，该结论此前建立在 test 上，须在 dev 重做。

## 3. 建议的方法组合

### T0 先让指标能看见信号（无训练，约 1 GPU 小时）
1. 统一评测矩阵：全 518 dev、3 个生成 seed、配对噪声/长度/文本、报配对 CI。
2. 主指标改为检索 MRR / top-1（`tools/probe_latent_retrieval.py`），SignMbart 只做汇报。
   准入门槛：新方法在 dev 上检索 MRR ≥ 1.5× 随机水平，才进入 BLEU/FVD 比较。
3. 每个模型固定报"相对地板（9.3 / 0.074）与上限（31.6 / 0.246）"的位置。

### T1 近免费增益（不改训练目标）
4. **采样预算与求解器（升为首要项）**：DDIM 50/100/250 → B1 9.47/9.17/10.88，
   B4 0.00/0.00/**2.77**，仍未饱和。先补 500 步确认拐点，再换二阶求解器
   （DPM-Solver++ / UniPC，x0-预测下 10–20 步常已超过 50 步 DDIM；文献 Lu et al. 2022；
   Zhao et al. 2023）。判据：同 checkpoint 同 seed，B4 上升且检索 MRR 不降。
   注意这条会让此前所有 50 步的比较失效，必须整表重算（换口径=换表，纪律第 5 条同理）。
5. **自条件化 self-conditioning**（Chen et al., Analog Bits, ICLR'23）：训练时以
   50% 概率把上一步 x0 估计拼进输入，推理时两轮迭代。对 x0-预测扩散是稳定增益，
   改动局限在模型输入、训练循环与采样循环。
6. **CFG 区间/动态调度 + rescale**：计划 E2。文献支持"前段强引导改善对齐、
   后段降低多样性"（2509.22007 阶段动力学；2509.16131 在线反馈；2608.14038 学习调度）。
   判据为检索 MRR 与 FVD 双指标。
7. **长度头升级**：分布化预测（分桶 + 期望/中位数回读）或直接用微调 mT5 回归；
   这是部署口径的纯损失项，收益直接体现在 BLEU 的 predicted-length 列。

### T2 主战场：把条件利用率做上去
8. **条件路径重构**（计划 E5）：prefix → 部分模态独立 QKV/FFN + 每层文本门控的
   联合注意力。先做 4 层双流的容量匹配对照（避免把容量增益当模态交互增益）。
9. **文本压力课程**：把固定 text dropout 0.10 改为课程（前期高 dropout 学无条件先验，
   后期降到 0.05），并加词级 dropout，防止只学句长/主题。
10. **文本分支优化器/特征层**：现 text_lr 1e-5 比主 lr 小 10×；可试文本侧更大 lr 或
   取 mT5 中间层特征接入条件（计划曾列为 P2）。
11. **表示对齐（REPA / iREPA）**：把 DiT 中间层特征对齐到本项目已有的视频 latent
    编码器（不用外部 pose，不违反硬约束）。REPA 在 ICLR'25、iREPA 在 ICLR'26
    报告了稳定的收敛加速与质量提升；本项目只需要一个"同模态、同步长"的对齐目标。
12. **多尺度 latent 动态损失**（计划 E4）：`ΔP_k(x0_pred)` vs `ΔP_k(z_GT)`，k=1/2/4，
    只约束时间结构，与语义 loss 正交。
13. **语义 loss 的可达性复核**（对应 H9）：先在真实 latent 上量 teacher gap（当前 0.675），
    再决定是否继续加权重；生成 latent 上的 gap 低说明瓶颈在生成器。
14. **更长/更宽训练作为正式对照**（对应 H3）：60k→120k/180k，以及 hidden 768→1024 或
    12→16 层的容量对照，都要在统一 dev 矩阵下与 5k 级方法增益同表比较。
    现有证据（60k→90k 的 +5.28 B1 与视频依赖的出现）说明这类"老办法"的期望增益
    高于计划里多数单因素改动，不能只当作后备。

### T3 战略级（需要用户裁决，见 §5）
14. **抬高表示上限**：上游 VAE 代码已有 `pixel_refine / extra_blocks` 开关（默认关闭，
    审计 M4 提到）。开启可提高解码保真，从而抬高 BLEU/FVD 上限，但触碰"冻结 VAE"约束。
15. **数据侧**：train 只有 7021 条。(a) 文本增强（德语同义改写/回译）提升条件多样性；
    (b) 引入外部手语数据集做第一阶段预训练（需要新 latent 缓存与文本桥，成本高）。
16. **推理期 best-of-N 重排**：用已验证 matcher 对同一文本采 4 条，取相似度最高者。
   必须在同一 N 下与基线对照，且不得用 SignMbart 重排。

## 8. 2026-10-14 傍晚追加：地板/锚点标定与注意力病理

### 8.1 退化 latent 控制：现役生成只比"静止真首帧"高约 1.9 B1

`tools/eval_vae_recon.py --mode {static,reverse,zero}`（`tools/run_anchor_controls.sh`）：
同一批 32 条 test、同一冻结 VAE、同一 GT 首帧锚点、同一解码路径，只改 latent。

| 控制（文本均为正确句） | BLEU-1 | BLEU-4 | ROUGE-L | WER↓ | FD(R2+1D)↓ | MRR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 真实 latent（表示上限，正放） | 31.56 | 14.93 | 29.32 | 91.8 | 28.37 | 0.246 |
| 静止：第 0 帧 latent 重复整段 | 7.55 | 1.88 | 8.17 | 101.4 | 160.8 | 0.123 |
| **逆序：真实 latent 倒放** | **14.97** | 2.79 | 12.80 | 111.9 | **32.07** | **0.241** |
| 全零 latent（只剩 GT 首帧锚点） | 4.66 | 0.00 | 4.62 | 99.4 | 709.2 | 0.127 |
| 现役 prefix-60k 生成（DDIM 50） | 9.47 | 0.00 | 9.57 | 114.2 | 51.61 | 0.135 |
| 错配真视频（地板） | 9.32 | 0.00 | 9.22 | 121.0 | — | — |
| 随机水平（MRR，N=32） | — | — | — | — | — | 0.127 |

读法三点：

1. **现役生成只比"一张静止的真首帧"高 1.9 B1**（9.47 vs 7.55），错配真视频还有 9.32。
   三条线挤在 2 个 B1 内，说明这一层指标主要在测"有没有一段像视频的像素"。
2. **逆序真视频（B1 14.97 / FVD 32.07 / MRR 0.241）比现役生成更好，几乎追平正放真视频
   （31.56 / 28.37 / 0.246）。** 也就是说：把一段真视频倒着放，回译 BLEU 仍高于我们最好的
   模型，FVD 只涨 3.7（28.4→32.1），检索 MRR 只掉 0.005。
3. 因此现有三个指标里：**FVD 与检索 MRR 基本对时间顺序不敏感**（≈顺序不变），BLEU-1 会掉一半
   （31.6→15.0）、BLEU-4 掉到 1/5（14.9→2.8）但计数太小。**"动作顺序/词序"正是 B4 与
   ROUGE 想测的东西，却是当前指标链最看不见的东西。** 任何只改善顺序的方法在这套指标下
   会被判成"没效果"。


### 8.2 检索 MRR 的可用量程（新标定）

| test-32 | 0.127 | 0.246 | 1.94× | prefix-90k 0.2206（DPM++ 50） |

两点结论：(a) 换到 MRR 是对的，但它**同样接近饱和**——prefix-90k 在 test-32 已经拿到

### 8.4 由此得到的评测结论（对 T0 的修订）

顺序不变性这条实验直接限定了可以拿什么当筛选指标：

- **FVD 不能单独当"动作对不对"的判据**：它对静止非常敏感（160.8/709.2），对时间顺序几乎
  不敏感（32.1 vs 28.4）。这与计划里引用的 "Content Bias in Fréchet Video Distance" 一致，
  本地用一种独立的退化方式复现了它。
- **检索 MRR 也不能单独当判据**：真实 latent 倒放仍有 0.241（正放 0.246、随机 0.127）。
  教师学到的是"这句话是什么"，不是"动作按什么顺序发生"。
- 可行补法（都只需现有数据，不需要新标注）：把"逆序""帧交换""时间打乱"三类对照与
  正确视频**同表报告**，并要求新方法在这三类对照上不被反超；或者加一个顺序敏感的小指标
  （例如用同一教师做"正放 vs 倒放"的二分类/似然差，或对帧序置换做排序测试）。
  判据建议写成："B4 不低于逆序真视频对照、MRR 不低于逆序对照、且 FVD 至少比静止对照低"。

### 8.5 CFG 在新求解器下仍然没调够：2.0 → 3.0 是免费增益（test-32）

prefix-60k、DPM++ 2M 50 步、raw、seed 42，只改 `guidance_scale`：

| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1.0 | 8.37 | 0.00 | 7.82 | 122.7 | 54.30 | 0.133 |
| 1.5 | 8.42 | 0.00 | 7.62 | 117.3 | 51.59 | 0.131 |
| 2.0（原默认） | 10.87 | 0.00 | 10.12 | 110.5 | 51.13 | 0.153 |
| 2.5 | 11.64 | 2.95 | 11.77 | 104.8 | 51.92 | 0.189 |
| 3.0 | **14.77** | **4.53** | **13.24** | **104.8** | 54.02 | **0.205** |

- CFG 2.0 是从 RefSign 继承的部署默认值，在新求解器下**没调到位**：3.0 把 B1 拉高 3.9、
  MRR 拉高 34%，代价是 FD 涨 2.9（51.13 → 54.02，仍远低于静止对照 160.8）。
- 这是继"换二阶求解器"之后第二个不重训就能拿到的增益。**但 n=32 的 B1 抖动 ±3**，
  所以决策必须在 dev-64 上做（`tools/run_cfg_sweep_dev64.sh`，2.5/3.0/3.5 在跑）。
- 与 T1.6（区间 CFG / 动态调度）的关系：静态 scale 既然还有收益，区间调度应在
  "静态最优点"之上再试，而不是从 2.0 开始。

### 8.6 同配置重跑的噪声：ΔB1 0.62（判断新方法前必须先看这个数）

同一 checkpoint（prefix-60k）、同一协议（dev-64、DPM++ 50、seed 42、CFG 2.0）、
两次独立运行（`reports/eval/prefix60k_dev64_dpmpp_o2_s50` 与
`reports/eval/dev64_prefix_ladder/prefix60k_correct`）：

| 量 | 结果 |
| --- | --- |
| latent 逐帧最大差 | 1.8e-4（bf16 采样/前向非确定性） |
| 解码帧字节 | 不一致 |
| BLEU-1 / ROUGE-L | 11.15 / 10.92 vs **11.77 / 11.20** |
| 差值 | **ΔB1 +0.62、ΔROUGE +0.28** |

叠加此前测到的回译阶段噪声（同帧重打分有 4/32 条译文变化，ΔB1 0.27），
**64 条 dev 上"同配置重跑"的 B1 波动约 0.5–0.6**。计划里 E1 的 λ 效应
（12.14 vs 11.52，Δ0.62）正好落在这个量级。结论：任何晋级/淘汰判据必须
(a) 用**配对**比较（同一批帧、同一初始噪声），或 (b) 明显大于 0.6 B1，否则就是在读噪声。

### 8.7 训练预算阶梯在 dev-64 上重做：指标互相矛盾（本轮最重要的口径警告）

`tools/reval_prefix_ladder_dev64.sh`，dev-64、DPM++ 2M 50、oracle 长度、CFG 2.0、
raw、seed 42，同一协议只换 checkpoint：

| checkpoint | BLEU-1 | BLEU-4 | ROUGE-L | WER↓ | FD↓ | 检索 MRR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| prefix-30k | 7.92 | 0.79 | 7.20 | 111.8 | 39.42 | 0.098 |
| prefix-60k | **11.77**（另一次同协议重跑 11.15） | 2.07 | **11.20** | 107.1 | 41.65 | 0.112 |
| prefix-90k | 8.08 | 0.00 | 8.59 | **105.2** | **40.86** | **0.144** |
| 真实 latent（上限，dev-64） | 31.71 | 10.32 | 33.61 | 87.9 | 23.55 | 0.199 |

配对 bootstrap（同 64 条视频、同参考文本，1000 次重采样，90k − 60k）：

| 指标 | 点估计 | 95% CI | P(有利) |
| --- | ---: | --- | ---: |
| BLEU-1 | **−3.69** | [−6.64, −0.58] | **0.01** |
| ROUGE-L | −2.61 | [−6.57, +0.88] | 0.08 |
| WER（改善） | +1.86 | [−5.28, +8.96] | 0.68 |

**结论（与 §0.3 相反，与旧 GFSLT 口径的"90k 不如 60k"一致）：在 BLEU/ROUGE 上 60k 明显更好，
在检索 MRR/WER/FD 上 90k 更好。** 两个指标给出相反排序，说明：

- 至少有一个指标在 n=64 上仍然不可靠。BLEU 侧我给了配对 CI（显著）；MRR 侧还没有
  噪声估计，但 MRR 的量程只有 0.074–0.199，0.112→0.144 相当于量程的 26%，也可能只是噪声。
- 现实含义：**"把训练拉长到 90k/120k"不能当作已证实的提指标手段**，必须先用
  ≥3 个生成 seed 的配对检验把 BLEU 与 MRR 的矛盾解开（同一 checkpoint、只换采样噪声）。
- 30k → 60k 两个指标都向上（B1 7.92→11.77、MRR 0.098→0.112），这是目前唯一
  两个指标一致的一步；**60k 是当前唯一"两个口径都支持"的预算点。**

（顺带：prefix-60k 同协议两次独立运行给 B1 11.15 / 11.77、MRR 0.112 / 0.112，
见 §8.6；因此 60k 与 90k 的 3.7 B1 差距大于重跑噪声，但小于 n=32 test 上的 ±3 B1 噪声，
这也解释了为什么旧 test-32 表会看到相反排序。）

### 8.8 dev-64 的错配真视频地板：7.56（第一次在筛选集上看到可分辨的间距）

`tools/make_rotated_video_control.py` 把每句参考文本配上下一条视频的帧（64 条 dev）：
