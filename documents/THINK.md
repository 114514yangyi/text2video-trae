### idea-002 · 局部软时序对齐损失

- **层级 / 动的瓶颈**：L2/E（监督目标错配：文本与帧之间没有对齐标注，纯逐帧 MSE 对合理的
  节奏偏移也施压）。
- **状态 / 日期**：`revived`；2026-10-14 立卡 → 2026-10-16 按 FAIL-025 出池 →
  **2026-10-18 用户裁决改判"回译侧有效"、复活**（旧裁决撤销，链路见 FAIL-025 补记二）。
- **去向 / 推荐顺位**：复活后待用户选出下一步——可选我：更大预算/更强实现重跑（按协议 P 重新
  预注册）；或先在 idea-029（细时间结构尺子）落地后用新尺子重判。
- **一句话做法**：在文本条件与视频 latent 之间加一条**窗口化软单调对齐损失**（允许局部跳过、
  整体保持方向），作用在 **DiT 可见的文本 context** 上，使梯度回到 `condition_encoder`
  （`t2v/models/softalign.py` + `t2v/train.py` softalign 分支）。
- **核心假设**：部分逐帧误差来自**合理节奏偏移**（动作稍早/稍晚）而非内容错误；显式软对齐
  比纯 MSE 更贴合目标，能让文本与视频在时间上对得更准。
- **预期增益区间 + 置信度**：该实现已有一臂正证据——route_q（20k、文本冻结）相对干净等预算
  对照 `route_s_cont20k`：**ΔB4 +1.07 [+0.40,+1.79] 显著正、ΔROUGE +1.29 [+0.15,+2.51]
  显著正**；ΔB1 +0.81 / ΔWER −1.15 方向偏好但不显著；ΔMRR +0.0001 不显著。置信度**中低**
  （单臂、单预算、实现形式未迭代）。
- **成本**：辅助损失改动中等（窗口化对齐的显存/时间开销需实测；R1 的 idea-024 已在
  `temporal_align.py` 里做过对角向量化提速，可借鉴）。训练臂成本 ≈ 20k 分叉 ~1h/臂。
- **风险与失败表现**：对齐把静止、遗漏或重复动作也判为正确；latent 距离不对应动作语义；
  损失权重过大改变去噪最优解。本臂未出现回译退化（WER 方向偏好），但 MRR 无变化。
- **最小证伪实验 + 判据**：① 前置"顺序信号可用"已 PASS（`reports/eval/temporal_order_probe_prefix60k.json`：
  倒序/块置换/静止的重建误差都显著高于原序）；② 效果判据走协议 P —— 该臂已过（见上）。
  **若重启更强形式/更大预算，须重新预注册判据**（FAIL-025 的原"可复活条件"：要能在**生成
  指标**上先做出正差异，本臂已在 B4/ROUGE 上做到）。
- **新颖性 / 去重 / 证据**：[Soft-DTW](https://proceedings.mlr.press/v70/cuturi17a.html) 与
  [DILATE](https://arxiv.org/abs/1909.09020) 支持可微时间匹配与形状/时间分离。区别于
  idea-024（对齐**生成与真实 latent**，允许 warp、不允许 cross）：本卡把**德语 token 按词序
  软映射到帧**。文献机制已核对，项目迁移有效性由 route_q 一臂给出"回译侧正"证据。
- **合规性**：H 全部满足——只用已有文本与目标 latent，不加对齐标注、不改缓存/VAE/x0 参数化；
  文本侧 `trainable` 按臂声明（route_q 为冻结）。
- **正式验收**：协议 P（test 642 单侧、同口径配对）；**读数注意 D3 的 MRR 尺子已饱和**
  （P9：最好臂达重建上限 97%；教师压到 64 bin 看不见细时间结构）——"回译正、MRR 不动"应与
  idea-029 一并解读。

### idea-020 · 用 D3 门槛/奖励做扩散后训练

- **层级 / 动的瓶颈**：L3；E（目标与评测不对齐——训练目标是 x0-MSE，评测真正在意的是检索 MRR/top-1 与回译质量，二者之间没有直接的优化压力）。
- **状态 / 日期**：`candidate`；2026-10-16。
- **去向 / 推荐顺位**：未选出；先做半天只读探针（奖励可利用性检查），通过后仍需用户裁决才进 TODO；D31 限制下本轮不新开训练臂；主战场3。
- **一句话做法**：在已训练好的扩散模型上做后训练，让"评测真正认可的样本"更容易被生成。两条可选路线：**(a) 奖励式**——按 TODO D29 用 SignMbart 作为训练期奖励，对生成结果打分并做策略梯度/漂移；**(b) 偏好式**——用"正确文本 vs 错配文本"的生成对构造偏好数据，做不需要奖励模型的扩散 DPO。
- **核心假设**：冻结 VAE 与现有训练配方已经到达一个"似然意义上不错、但评测意义上没被优化"的解；在推理期条件不变的前提下，只要后训练信号与评测同向，就能把生成往可检索、可回译的方向推。CFG 放大已给 +6.4 B1，说明推理/优化侧确实还有未被消化掉的余量。
- **预期增益区间 + 置信度**：B1 约 +1~4；置信度**中**；风险高（奖励作弊）。
- **成本**：先半天只读探针（不训练）；若通过，奖励式与偏好式各需一条后训练臂 + 协议 P 评测，成本另计（受 D31 限制，需用户另行放行）。
- **风险与失败表现**：**奖励作弊是首要风险**。D24 已实测：现有教师偏好正确文本、拒绝静止视频，但**分不清倒放/块置换**；若直接把这类奖励接进后训练，模型可能学会"生成倒放/无时序的样本"来骗分。因此直接可用于本卡的奖励必须先通过"能否同时区分倒放与块置换"的检查。失败表现：奖励上升而 MRR/top-1 不动或下降；或因优化目标与 D3 门槛不同源（SignMbart 奖励 + SignMbart 汇报）造成同源自证，须在汇报时明确标注该风险，晋级仍以 D3 检索为准。
- **最小证伪实验 + 判据**：不训练，只测。取现有生成 latent，沿奖励梯度做小扰动，观察"奖励上升的样本是否同时具备更好的检索/时序正确性"。**判据**：若奖励更高的样本包含更多倒放/块置换这类时序退化，或奖励上升而 MRR 不升，则判定该奖励不可直接用于后训练，关闭路线 (a)；若要保留，须先换更可靠的奖励或改用不依赖该奖励的偏好路线 (b)，并满足原 idea-009 的"选择器与评测器不同源"精神。这是前置否决探针，探针通过不晋级。
- **新颖性 / 去重 / 证据**：来源 PRDP（arXiv 2402.08714，题名 *Proximal Reward Difference Prediction for Large-Scale Reward Finetuning of Diffusion Models*，本轮已核验题名）与 arXiv 2311.13231（题名 *Using Human Feedback to Fine-tune Diffusion Models without Any Reward Model*，本轮已核验题名）；后者说明偏好式路线**可以不需要训练奖励模型**，天然避开一部分奖励作弊风险。仓库侧支撑：D3 已把 MRR/top-1 定为晋级门槛，而现有训练目标是 x0-MSE，两者不对齐；CFG 放大给 +6.4 B1 说明推理期还有余量。与 idea-005 的区别：005 是"先训练一个可靠教师再门控提供梯度"，本卡是"直接用评测向信号做后训练"，两者在"奖励可靠性"这一前置上共享检查。与已取消的 idea-009（推理期 best-of-N 重排）不同：009 是推理期选择，本卡改的是权重。
- **合规性**：H 全部满足——推理期条件仍只有文本与文本预测的部署长度，无 pose/reference/gloss/光流；不改冻结 VAE、不换 latent 空间、保持 x0 输出。训练期奖励按 D29 允许使用 SignMbart，但汇报同口径指标须标注同源自证风险，晋级仍以 D3 检索 MRR/top-1 为准。按 **D34** 本卡不涉及文本侧微调，必要时可显式开启并声明；后训练属新增训练臂，须先获用户放行。
- **正式验收**：统一协议 P；MRR/top-1 为门槛，SignMbart 与 FVD 只汇报；半天探针不晋级。

### idea-024 · 受限时间对齐的 latent 辅助损失

- **层级 / 动的瓶颈**：L2/E监督目标错配。
- **状态 / 日期**：`candidate`；2026-10-16；用户要求记录方法，尚未选为执行任务。
- **去向 / 推荐顺位**：优先小规模验证；仅入 THINK，不进入训练队列；遵守“先给方法，暂不开训练”。
- **一句话做法**：保留原始去噪 MSE，增加生成 x0 与真实 latent 序列的局部时间对齐损失，并惩罚过度拉伸。允许正确动作稍早或稍晚出现，不允许任意跳过动作。
- **核心假设**：部分逐帧误差来自合理节奏偏移；区分动作内容与精确出现时间，可能减少错误训练压力。此归因尚未由本项目证实。
- **预期增益区间 + 置信度**：BLEU-4 增益区间无法可靠估计；置信度低。接近 10 是研究目标，不是本卡的实测结果或收益承诺；跨领域论文指标不能换算为本项目增益。
- **成本**：辅助损失改动中等；动态规划可能增加时间和显存，先测带宽限制版本。
- **风险与失败表现**：对齐将静止、遗漏或重复动作也判为正确；latent 距离不对应动作语义；替代 MSE 会改变去噪最优解。
- **最小证伪实验 + 判据**：半天内用真实 latent 构造轻微变速、倒序和静止重复，检查损失是否宽容轻微变速却惩罚倒序/静止。若退化样本也得低损失，否决当前损失；性质检查不代表 BLEU 提升。
- **新颖性 / 去重 / 证据**：[Soft-DTW](https://proceedings.mlr.press/v70/cuturi17a.html)、[DILATE](https://arxiv.org/abs/1909.09020) 支持可微时间匹配与形状/时间分离。区别于 idea-002：本卡对齐生成视频与真实视频 latent，不把德语 token 按词序硬映射到帧。 文献机制已核对，项目迁移有效性和新颖性均未证明。
- **合规性**：只用已有目标 latent 与文本；不改缓存；原始 x0 去噪目标保留，辅助项权重须受控。 统一遵守 H、D34；本卡默认不动文本编码器（如要微调须显式声明）；VAE 冻结，生成保持原 latent 空间的 x0 预测。
- **正式验收**：协议 P，test642 同口径配对，报告 BLEU-4 及其他回译指标，保持 D3/D20 晋级约束；新采样方式需报告 NFE/耗时，并区分等预算比较与机制消融。小样本机制诊断不能晋级。

### idea-042 · 解码空间的内容目标（DVO：Decode-Verify Objective）

- **层级 / 动的瓶颈**：L3/E。**目标与指标之间隔着两级冻结读出**：我们优化的是 latent 空间的
  x0-MSE，但北极星是"把解码出的视频送进冻结 SignMbart 读出的德语与参考句的 B4"。全表实测：
  dev MSE 已收敛到 0.02–0.04 量级，而 70 条 test-642 臂的 B4 中位数只有 **1.97**、最好臂
  `route_t_align_20k_ema` 只有 **4.66**（2026-10-20 现役最强已更新为 `route_t_align_20k_ema_k4` = **5.65**）；同时**同一个 VAE 的重建上界是 B4 13.58**、GT 视频是
  **22.74**。⇒ 生成器只兑现了自己表示能力的 **34%**，而 MSE 对此毫无感知。
- **状态 / 日期**：`candidate`；2026-10-19 新立（由本日 70 臂全表复核、AGENTS 北极星 D44 与
  红队裁决共同驱动）。
- **去向 / 推荐顺位**：待用户选出。**前置 = 「解码容差曲线」免训练探针**（在 §4 与
  `TODO.md` 登记）。主战场 · 目标对齐。
- **一句话做法**：训练每步在采样到的 t 上取 x0 预测 **ẑ**，用**冻结 VAE 解码到像素**，过
  **冻结 SignMbart**，对**参考文本**取 teacher-forcing 序列 CE（或 BLEU/ROUGE 的软代理），
  得到标量 `L_dvo`，按权重 λ 加回总损失。改动点：`t2v/train.py` 新增 `dvo_loss` 分支；
  复用 `t2v/adapters/vae.py`（只读）与 SignMbart 包装（只读）；`t2v/models/` 不动。施加范围
  限定为 t 较大的段（内容尚未定型）并对 batch 抽样（如 1/4 样本）以控成本。
- **核心假设**：能被**读出来**的内容才是北极星。在 latent 上做各维等权 L2 会把概率质量放到
  "平均动作"上，而"解码器 + 回译者"这条链只认**具体的义素动作序列**——所以损失的形状必须是
  读出的形状，而不是 latent 的形状。
- **预期增益区间 + 置信度**：B4 **+1.5 ~ +4.0**（从 5.65 推向 7–9.5）；置信度**中低**。机制
  直接对准指标是优点，风险在梯度质量与成本。**明确不承诺 ≥10。**
- **成本**：需先实测单步开销。已测基准：VAE 解码约 5 s / 32 条（≈0.16 s/条）、SignMbart 约
  2 s / 32 条（≈0.06 s/条）；现役训练 0.43 s/step（batch 16）。抽 4 条施加 → 约 +0.9 s/step
  （≈1.3 s/step），20k 分叉臂 ≈7.2 h；降档（每 4 步一次 + 抽 2 条）约 +0.2 s/step。
- **风险与失败表现**：① **奖励作弊**——SignMbart 只在已训练词表上工作，模型可能靠生成高频
  德语天气句压低 CE 而不生成正确内容；必须按 D24 口径先做教师/读出可靠性检查，并要求
  B4/ROUGE 与 WER **同向**才认账。② **实现风险**——解码与回译必须在 `no_grad` 内跑，回传到
  ẑ 需要自定义 `autograd.Function`（后向重算或有限差分），这是本卡最大的工程不确定性。
  ③ **机制被前置否决**——若容差曲线显示"latent 误差很大时内容仍可读出"，则说明瓶颈不在读出端，
  本卡直接出池。
- **最小证伪实验 + 判据**：
  **前置（免训练，≈1 GPU·h）「解码容差曲线」**——取 642 test 的 GT latent `z*`，加
  σ ∈ {0, 0.05, 0.1, 0.2, 0.4} 的高斯扰动（并可加时间低通档），解码 → SignMbart 回译 → 报
  语料级 B1/B4；同时报现役最强臂每个样本的 `‖ẑ − z*‖` 分位数。判读：若模型的误差分位数落在
  "B4 已经为 0"的 σ 区，则瓶颈是**回归精度**（该改优化/容量/数据，不必上 DVO）；若落在
  "B4 还能读出但对不上内容"的 σ 区，则 DVO 是对症的解。
  **后置（最小臂）**——20k 分叉 vs `route_s_cont20k` 等预算对照，协议 P；主判据 **B4/ROUGE
  显著正且 WER 不退化**。
- **新颖性 / 去重 / 证据**：机制来源是 DRaFT / ReFL / Diffusion-DPO 一族的"把下游可微目标
  反传进扩散"。**与 idea-020 不同**：idea-020 是"用 D3 检索门槛/奖励做**后训练**"（对采样
  轨迹做策略优化、奖励是序列级标量），本卡是在**正向训练**里对**单步 x0 预测**施加**可微读出
  损失**，属于目标函数替换而非策略优化；两卡可叠加但判据分开。与 FAIL-021/023/026 的失败模式
  **不同轴**——那三条是"加在**条件路径**上的硬性约束把生成推向检索友好、回译退化"，本卡不动
  条件接口，只动损失。前置证据：NOTES 2026-10-19 错配真视频（真视频 + 错字幕）**B1 9.32 /
  B4 0.00**，且配对 bootstrap 与现役生成 **ΔB1 +0.16 [−5.03,+5.13]、P=0.57（不可分）**；
  倒放真视频仍优于现役生成 → **读出端对"内容对不对"极度敏感、对"视频像不像"不敏感**，
  这正是本卡要把损失搬到读出端的理由。
- **合规性**：H 全部满足——冻结 VAE 只作只读前向，不改 latent 缓存/空间/x0 参数化；SignMbart
  按 D29 可作训练信号，汇报时须标注**同源自证风险**；不引入 pose/gloss/光流。
- **正式验收**：协议 P（test 642 单侧、同 EMA/CFG/长度/种子口径配对）；**晋级只认 B4/ROUGE
  显著正且 WER 不退化，MRR 不得单独放行**（红队意见 + FAIL-021/023/026 教训）。

### idea-043 · 解码敏感度加权的 latent 损失（decoder-aware loss shaping）

- **层级 / 动的瓶颈**：L2/E。与 idea-042 同一个不对齐问题，但**只改损失权重、不引入回译梯度**，
  是它的低风险、低上限替身。
- **状态 / 日期**：`candidate`；2026-10-19 新立。
- **去向 / 推荐顺位**：待用户选出；与 idea-039（按帧数加权）须**分别与合并**各跑一臂以免归因
  不清。后备 · 损失整形。
- **一句话做法**：离线估计"冻结 VAE 解码器对哪一个 latent 维/时间位置敏感"——对每个 latent 维
  施加固定幅度扰动、解码、量像素（或解码器特征）变化，得到 `[1024]` 敏感度向量；训练时把现役
  各维等权的 x0-MSE 换成"敏感度 × 帧数权重"的逐元素加权。
- **核心假设**：1-token/1024 维 VAE 的各维对"读出来的内容"贡献极不均；把梯度预算从解码器
  看不见的维挪到看得见的维，能在**不引入循环依赖**的前提下改善读出内容。
- **预期增益区间 + 置信度**：B4 **+0.3 ~ +1.2**；置信度**低-中**——重加权类改动在本项目历史
  上收益都不大，本卡的区别只在于权重依据来自下游敏感度而非拍脑袋。
- **成本**：离线敏感度估计 ≈0.5 GPU·h；每分叉臂 ≈1.7 h；训练开销近零。
- **风险与失败表现**：① 最敏感的维可能是"高频噪声"维，放大它们只会更噪不更好；② 与 idea-039
  的权重方案可能互相抵消。
- **最小证伪实验 + 判据**：**离线先看敏感度分布**——若 top-10% 维贡献不到 50% 的像素变化
  （即各维贡献均匀），则本卡机制不成立、直接出池；否则跑 20k 分叉臂 vs `route_s_cont20k`，
  判据同 idea-042。
- **新颖性 / 去重 / 证据**：与 idea-039（**样本/帧**权重）、idea-031（**噪声阶段**权重）
  都不同轴——本卡是**特征维**权重。解码器敏感度作为损失权重在视频扩散里有先例（感知损失一族
  的"解码器感知"思想），本项目从未试过。
- **合规性**：H 全部满足；不引入任何新监督来源。
- **正式验收**：协议 P；判据同 idea-042。


### idea-044 · 旗舰组合臂的归因消融包（原 idea-039 / 040 / 041 合并）

- **层级 / 动的瓶颈**：L1-L2/E。**不是新机制**，而是对 2026-10-19 已跑完的 `flagship_ref_v1`

- **状态 / 日期**：`candidate`；2026-10-19 合并新立（由 idea-039 / 040 / 041 三卡合并而来——这三张

### idea-045 · 迁移 Wan2.1-1.3B 预训练骨干（重接 I/O，继承 30 层块 + umT5-xxl 文本通路）

- **层级 / 动的瓶颈**：**L3/R（表示与先验）**。动的**不是**"去噪能力"，而是**"听文本的能力"**。
  归因依据：① 错配地板（真视频 + 错字幕）`B1 9.32 / B4 0.00`，说明 B4 几乎不取决于"像不像手语"；
  ② 内容词召回：真视频回译 ≈55%，现役最强臂 `route_t_align_20k_ema`（B4 4.66；`_ema_k4` 5.65 时为 6.8%）只有 **5.7%**，
  86.3% 的样本召回为 0（与常数高频词表的 1.20% 同量级）；③ `NOTES` 通道解剖：换文本后
  cross-attn 输出变化 0.89–1.64，但 block 隐状态只变 4–6%、最终输出只变 ~1%，**cross-attn 的
  有效贡献只有 MLP 的 3–12%**。⇒ 我们缺的不是去噪，是**文本跟随**。
- **状态 / 日期**：`candidate`；2026-10-19 用户指定"使用 Wan 模型"方向后新立。方案全文见
  `.trae/documents/WAN_BACKBONE_PLAN.md`（含事实核查、架构适配、成本、风险与开放问题）。
  **2026-10-20 实测结果（exp-094，`wan_flow_mlp4096_motion_v2`）：判失败。**B4 **1.13** / B1 9.16 / ROUGE 9.12 / WER **120.62**（劣于错配真视频地板 119.46）/ FVD **66.92**（重建上限的 4.6 倍）/ 内容词召回 **3.0%**（随机字幕基线 1.53%）。三项硬指标一致指向"无信号"；而训练侧本身正常（桥 cos 0.9968、loss 2.01→1.03、dev/mse 解释 53% 方差）⇒ **失效点在「冻结视频扩散先验 → 1-token/帧抽象 latent」这一环**。**待用户确认后出池（并入 FAIL.md）。**
- **去向 / 推荐顺位**：待用户拍板 `WAN_BACKBONE_PLAN.md` §10 的五个开放问题。**主战场 · 唯一
  尚未试过的轴**（"改条件接口 / 改生成结构 / 改损失形状"三轴已被 40 次实验系统性证伪）。
- **一句话做法**：把 Wan2.1-1.3B 的 30 层 transformer 块（连同配套的 `text_embedding` +
  umT5-xxl 文本塔）整体迁移过来，只把 **I/O 两层换掉**——`patch_embedding` 由
  `Conv3d(16→1536,(1,2,2))` 改成 `Conv3d(1024→1536,(1,1,1))`（每帧恰好 1 个 token），`head` 由
  `Linear(1536→64)` 改成 `Linear(1536→1024)`；新建参数仅 ≈3.1M，继承 ≈1416M。**不做 latent
  适配器**（否则会把证伪实验的因果搞浑）。
- **核心假设（可证伪）**：**H-Wan = 把 Wan 的块连同它配套的文本通路当初始化，能把"文本跟随"
  这个行为迁移到我们的 1024 维/帧 latent 空间，从而把内容词召回从 ~6% 抬起来，进而把 B4 从
  5.65 推向 10。**
- **预期增益区间 + 置信度**：**不承诺 B4 ≥10**。区间 0 ~ +5，**置信度低**——主风险是表示错配
  （Wan 块学的是它自己 VAE 隐空间的纹理去噪，我们是手语专用语义码）。**但证伪成本只要 2 GPU·h**，
  这是它优于其它 L3 设想的地方。
- **成本**：Stage 0 环境+下载+读源码 0.5 天（0 GPU）；Stage 1 冒烟 0.5 GPU·h；Stage 2 证伪
  2×2 GPU·h；Stage 3 正式臂 8–12 GPU·h；Stage 4 归因 6–8 GPU·h。**合计 ≈20–30 GPU·h**。
  下载 17.0 GB（可先 5.68 GB）+ umT5 文本嵌入缓存 4.3 GB，**磁盘净需求 ≥30 GB（现仅 53 GB 可用）**。
- **风险与失败表现**：R1 表示错配（Stage 2 打不过随机块 ⇒ 停）；R2 文本塔接错（换成 mT5-base
  + 新投影会**直接毁掉**我们最想要的先验 ⇒ 强制用 umT5-xxl 且冻结）；R3 latent 尺度不匹配
  （不做 `train_stats` 固定标准化则 loss 不降）；R4 RoPE 在 `grid_sizes=(T,1,1)` 下有效旋转子空间
  只剩 ~34%；R5 磁盘不足；R6 环境缺 `diffusers`/`peft`；R7 **容量解释**（无等容量对照必自欺，
  项目已在 FAIL-019/024/034 栽过三次）。
- **最小证伪实验 + 判据**：**Stage 2**——同一 2k 步预算下比两条臂：`wan-io`（Wan 预训练块**冻结**、
  只训新 I/O）vs `wan-io-rand`（**等容量随机初始化** 30 层、同样只训 I/O）。判据（**预注册**）：
  ① `wan-io` 的验证 x0-MSE 显著低于对照（按帧配对，**p < 0.01**）；② 相对优势 **≥5%**。
  两条任一不满足 ⇒ "预训练先验可迁移"证伪，**整条路线关闭并写 FAIL**。
- **新颖性 / 去重 / 证据**：本项目从未试过"换预训练骨干"这条轴（40 次实验全在自研小 DiT 上改
  条件/结构/损失）。选 Wan 而非 CogVideoX 的**第一条硬理由**是它的 `patch_size=(1,2,2)` —— **时间维
  不压缩**，把空间网格设成 `H'=W'=1` 后 patch 核退化成 `(1,1,1)`，**天然对上我们"每帧 1 token"**，

  latent 空间扩散 ✅；x0 输出 —— ⚠️ **RULES 第 3 条与 Wan 原生的 velocity 目标正面冲突**。首选
