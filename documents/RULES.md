## 0. 知识库版本管理规范（2026-10-20 用户指令，**优先级高于本文其余全部执行偏好**）

**`.trae/` 整个目录不进入 git 管理。**

### 0.1 规则

1. `.trae/` 已在 `.gitignore` 中**整体**忽略（不是只忽略 `.trae/reference/`），不得再被 `git add` / 提交；
2. 历史提交中的 `.trae` 记录已于 2026-10-20 清除（`git filter-branch` 全分支重写：38 个 commit / 4 个分支）；
3. **`.trae` 下的一切修改都不产生 commit**：改完 THINK / TODO / NOTES / FAIL / FINISH / EXPERIMENT / RULES，
   **不要** `git add .trae`，也不要为此单独提交；
4. `git checkout <branch>` / `git switch` **不会改动 `.trae`**，所以切分支后知识库保持原样。

### 0.2 为什么

知识库（`THINK` / `TODO` / `NOTES` / `FAIL` / `EXPERIMENT` / `FINISH`）记录的是**方法演进与判断依据**，
必须**跨方法、跨分支连续可查**。若它跟着 git 走，会出现三个坏结果：

- **切分支就"失忆"**：从 `main` 切到 `wan-backbone`，`.trae` 被检出成旧版本，
  当前分支上的实验台账（`exp-NNN`）看着凭空消失，或反过来被旧内容覆盖；
- **合并冲突落在知识库上**：多分支并行时 `EXPERIMENT.md` / `TODO.md` 几乎每行都冲突，
  解决冲突的成本远高于收益，且极易把结论改错；
- **历史污染**：每个实验都要改一次台账，commit 大量变成纯文档噪音，真正的方法改动被埋掉。

反过来，`.trae` 脱离 git 的代价很小：它不需要回滚（结论只增不删）、不需要分支隔离（**它本来就该全局唯一**）。

### 0.3 追溯与备份怎么办

- **追溯靠台账自身**：`EXPERIMENT.md` 行只增不删、`FAIL.md` 保留完整失败链路、
  `TODO.md` 记录决策 `D-NNN`。时间线由这些 ID 保证，不依赖 `git log`；
- **备份靠仓库外副本**：需要留档时把 `.trae/` 打包到 `/tmp` 或项目外，**不要**用 git 存；
- 若确实需要版本历史，用独立仓库（`.trae/.git` 自成一体）或项目外快照，不与代码仓库共享 commit 图。

### 0.4 清理记录（一次性操作，2026-10-20）

- **备份**：`/tmp/text2video-pre-trae-purge-20261020.bundle`（`git bundle` 全量，含清理前 4 个分支的完整历史）；
- **回滚方式**：`git clone /tmp/text2video-pre-trae-purge-20261020.bundle <dir>` 即可恢复清理前的仓库（含 `.trae` 历史）；
- **清理后校验**：`git log --all -- .trae` 为空、`git ls-files .trae` 为空，`.trae/` 文件仍在磁盘上且内容未变。

## 授权边界规范（2026-10-19 用户指令，**优先级高于本文其余全部执行偏好**）

**默认状态 = 方案模式（proposal-only）。** 未被明确授权"动手"时，只输出设计方案供用户审阅：
不得修改 `t2v/`、`tools/`、`configs/`、`tests/` 下任何代码，不得新建脚本，
不得启动任何训练/评测作业，不得下载大体积权重，不得删除或移动已有产物。

### 1. 两种授权模式

| 模式 | 触发语 | 允许做什么 | 交付物 |
| --- | --- | --- | --- |
| **方案模式（默认）** | 分析 / 评估 / 看看 / 调研 / 设想 / 讨论 / 你觉得 / 怎么改 / 提 idea / 帮我想 | 只读：读代码、读日志、读指标、跑纯 CPU 只读探针、写/改 `.trae/documents` 下的方案文档 | 方案：改动点（文件:行 + 张量形状）、判据、成本（GPU·h）、风险、替代方案。**到此停下** |
| **执行模式** | 写 / 改 / 实现 / 跑 / 训练 / 执行 / 直接做 / 按这个做 | 写代码、建脚本、起训练与评测作业、git commit | 代码 + 命令输出证据 + EXPERIMENT/TODO 台账登记 |

### 2. 判定规则

1. **只认明确指令。** "你没说不行就是可以"不成立；"上次这么做过了"不成立；
   "这是显然的下一步"不成立；"反正闲着也是闲着"不成立。
2. **方案模式的收尾必须停住**：给出方案后写"等你确认后再动手"，不自行推进到执行阶段。
3. **授权不延伸。** 一个任务里拿到的授权只在那一件事上有效：
   - "评估 X 方案" ≠ "实现 X"；
   - "实现 X" ≠ "起训练跑 X"；
   - "跑这个臂" ≠ "顺手把它后续的评测/对比/调参全排上去"。
   需要下一段授权时**明确问一句**，不默认继承。
4. **只读诊断不受限**：读文件、`grep`、看指标、跑不写仓库且不占 GPU 的只读探针，
   属于方案模式的一部分，可以直接做。
5. **执行中修自己刚写的 bug 不算越权**：在已授权的执行任务内，
   修本轮自己引入的缺陷属于同一任务，不必再申请一次。
6. **报告要分清"已做"与"建议做"**：方案模式下禁止出现任何暗示动作已执行的措辞。

### 3. 破坏性操作额外加一道闸

删文件、清 `runs/`、改 `RULES.md` / `AGENTS.md`、改冻结契约、覆盖已有实验产物 ——
**即使处在执行模式**，也必须先把「要动什么 / 为什么 / 影响范围 / 回滚方式」写给用户看过再动。

### 4. 这条为什么放在最前面

2026-10-19：用户只要求"评估 Wan2.1-1.3B 做骨干的方案"，agent 自行推进到改代码、
下 27 GB 权重、起 2 万步训练。产物没被浪费，但**判断权被抢走了**。
方案可以错三次再改；动手只有一次机会，收不回来。

## 方法硬约束（2026-10-12 用户指令，高于一切其余偏好）

后续所有对模型/方法/配方的改造都必须同时满足以下六条，缺一不可：

1. **VAE 固定**：视频生成必须基于此前已训练好的 1-token（每帧 1024 维）冻结 VAE，
   不得更换 tokenizer/VAE 或改动其冻结契约（缓存/统计/checkpoint 只读）。
2. **latent 扩散**：扩散过程在 VAE latent 空间进行（不回到像素态做 diffusion）。
3. **预测目标：x0 或 velocity，二选一且必须显式声明（2026-10-19 用户修订）**：
   默认仍是 **x-prediction**（网络预测 x0，`prediction_type: x0`）——这是历史全部
   88 个实验的口径，保持不变。**新臂允许使用 flow matching / rectified-flow**
   （网络预测速度 `v = x0 − ε`，`prediction_type: velocity`），但必须同时满足：
   - 在 config 显式声明 `prediction_type`（`x0` | `velocity`）与配套 `scheduler`；
   - **换目标/换采样器 = 换口径**：velocity 臂用 FlowMatchEuler（或 UniPC），
     与 DPM-Solver++ 臂**不得混表直接比**；跨口径比较必须显式标注，或另跑等预算的
     "同骨干 + x0"对照把"换目标"与"换骨干"两个变量分开；
   - **latent 仍必须是冻结 VAE 的 1024 维/帧**（约束 1、2 不变）。
   数学上 x0 / ε / v 三者线性等价，但在本项目里它们是**实质不同的选择**：exp-064 实测
   现有 x0-MSE 口径下 **t≥500 占 loss 权重 97.94%、t=950 单独占 75.35%**，而
   velocity-MSE 对所有 t 等权——用哪个坐标直接决定模型把梯度花在哪。
   决策登记 TODO **D49**。
4. **条件来源（2026-10-19 用户修订，取代原"纯 text→video"）**：生成条件 = **文本**
   （部署时长度若需要，由文本预测得到）+ **参考帧 frame 0**（`ref_features [128,512]`，经 DiT
   cross-attn context 与 adaLN 全局向量注入，即 `conditioning.reference.enabled: true`；
   对应用户指定的"方法 4"）。部署接口相应变为 **`text + frame0 → video`**。
   仍**不得**引入 pose、gloss、光流等其它监督/条件信号（VAE 解码锚点属冻结 VAE 固有解码输入）。
   原"纯 text→video"设定降级为**可选消融口径**，其历史数字不得与本口径混表。
   约束 1/2/3（冻结 VAE、latent 扩散、x-prediction）与 5/6 不变。决策登记 TODO **D45**。
5. **对比指标固定为 videovaet_fvd 的 per-clip FVD（2026-10-29 用户指令，取代此前全部 FVD 规则）**：
   此后所有方法/超参/采样器/训练预算的对比与晋级，**唯一主指标 = videovaet_fvd 的 `fvd_mean`**：
   `FVD (VideoVAET videogpt I3D-K400 logits, 24 frames, 224² stretch, per-clip mean, N=640)`。
   口径唯一来源是 `.trae/documents/FVD_SPEC.md`，实现 `tools/eval_videovaet_fvd.py`
   （调用 `/data/huyang/SignVIP/videovaet_fvd`，`VIDEOVAET_FVD_ROOT` 可覆盖），
   改动后必须先跑该包自带的 `bin/videovaet-fvd verify` 与 `selftest`
   （期望 `fvd_mean = 0.5694066286087036`），并同时报告 `floor.fvd_mean`（真值互配本底）。
   - **旧口径全部作废**：`R(2+1)D-18 avgpool`（22–26、51.6–58.4）、16 帧 `tools/eval_fvd.py`
     （132–185）、32 帧 SignViP 口径、以及 2026-10-27 的 `video_metric/styleganv`
     （84 本底、128–142）**都不得再引用、不得与新数字混表**——它们连估计量都不同
     （pooled Fréchet vs 逐 clip 均值距离）。
   - **回译（SignMbart）不再要求、不再作为对比/晋级指标**；个别语义分析若仍要看回译，
     只作可选诊断，仍必须走 SignMbart 原协议，且不得与 FVD 主表混排。
   - **报告格式**：FVD 数字必须带 backbone/frames/分辨率/N、`protocol` 块与 `floor`；
     只写 "FVD" 而不注明口径的数字视为无效。

6. **文本编码器可微调，但必须显式声明（2026-10-17 用户指令，取代 D30）**：新建训练臂可以
   **自由选择** `conditioning.text` 是冻结还是微调（全量微调、LoRA、部分解冻都可），
   不再有"新臂默认冻结文本编码器"的限制。文本微调视为**正常实验变量**，可与 DiT 结构、
   条件接口、训练目标等其他变量一起进对照与晋级流程。
   - **唯一硬性要求 = 声明**：每条臂的配置、`TODO`/`FINISH`/`EXPERIMENT` 记录都必须写明
     文本侧**是否可训练**（`trainable` 取值）与文本侧学习率；未标注的臂不得拿来当对照，
     也不得作为"文本侧改变带来增益/损失"的因果证据。历史教训 `FAIL-006`：route A 的
     对照臂本身也开了文本训练却未标注，导致那一轮的因果读不出来——被禁止的从来不是微调，
     而是**没标清楚到底训没训**。
   - **不算微调的情形**：只读地改变读取哪一层冻结表示（如 `route_n_mt5mid6_30k` 用
     `hidden_layer: 6`）不产生可训练文本参数，仍按"冻结文本侧"归类；分类时以
     `conditioning.text.trainable` 的实际取值为准。
   - **口径一致性**：比较两臂时须确认两侧文本侧状态相同，或把文本侧状态本身作为被检验的
     变量并显式写出；混着比而不声明等于无效对照。
   - **历史臂**：`route_g_textlr5e5_20k`、`route_g_textlr1e4_20k`、`route_n_mt5mid6_30k`
     等原地保留、不重算、不删除；它们的结论按当时的文本侧状态照旧成立。
   - 决策登记见 `TODO.md` **D34**（D30 已被取代）。

## 知识库流转规范（2026-10-14 用户指令，必须遵守）

8. **中间产物一律入 `.trae`**：计划、方案、思考、调研、审计、评审、brainstorm、思辨/复盘等
   "过程类"文档，一律写在 `.trae/documents/` 下，命名 `<主题>_<类型>_<YYYYMMDD>.md`
   （例：`PLAN_20261014_cfg_interval.md`、`BRAINSTORM_TOPIC_20261014.md`）。
   **禁止**散落到仓库根目录、`docs/`、`reports/` 或别处 —— `reports/` 只放评测数字产物，
   `runs/` 只放训练产物。旧 `docs/` 目录内容已于 2026-10-14 整体迁入 `.trae/documents/`，
   该目录作废、不再新建；外部技能（如 superpowers 的 writing-plans）产出的计划也要落到这里。

9. **四态流转：think → todo → finish → note / fail**（设想、任务、产物、结论分开存放）：
   - **think**（`.trae/documents/THINK.md`）：新的设想/idea 先登记成卡片（编号 `idea-NNN` 只增不复用），
     必填字段 = 层级 / 动的瓶颈 / 一句话做法 / 核心假设 / 预期增益区间 + 置信度 / 成本 /
     风险与失败表现 / 最小证伪实验 + 判据 / 合规性（对照方法硬约束）/ 日期。
     `candidate → accepted`（是否值得试）由**用户裁决**；agent 可补全成本、判据、证据与优先级建议，
     但不得自行开工，除非用户明说"按你推荐的顺序做"。
   - **todo**（`.trae/todo/TODO.md`）：选中的设想把"要做的事 / 要改的代码"写成任务条目，
     同时在卡片"去向"字段回填 TODO 编号；TODO 只保留**未完成**条目。
   - **finish**（`.trae/documents/FINISH.md`）：该条目做完后**从 TODO 剔除**（编号不复用），
     把产物路径 / 复现命令 / 判据 / 现状数字登记到 FINISH，等待测试。
     ✅ 用户测试裁决后**出池**：
     - 认为**有提高** → 从 THINK 与 FINISH 删除，结论写入 **note**（`.trae/documents/NOTES.md`）；
     - 认为**没用** → 从 THINK 与 FINISH 删除，写入 **fail**（`.trae/documents/FAIL.md`），
       并记录"从 think 一直到最终测试"的完整失败链路（来源设想 / 做法 / 预注册判据 / 实测结果 /
       证据路径 / 结论 / 是否可复活）。
   - 出池是单向的：THINK 只留未裁决的设想，FINISH 只留未裁决的产物。
10. **结论可检索**：出池后在 NOTES / FAIL 中保留 `idea-NNN` 编号与产物路径，
   使"这个想法试过没有、结果如何"可以直接搜到；被证伪路线的条目不覆盖不删除，
   若被新证据推翻，另立新条目并在旧条目注明取代关系。

11. **调研/思考类提问默认不落盘（2026-10-14 用户指令）**：
   - 用户以提问形式要求"调研一下 X""你现在怎么看 Y""帮我分析 Z""最新论文怎么说"这类
     **调研类 / 思考类**内容时，默认**只在对话里回答**；不新建文档，也不追加进
     `.trae/documents/`（包括 `<主题>_<类型>_<日期>.md` 这类调研/分析报告）。

## 资源使用规范（2026-10-16 用户指令，必须遵守）

14. **GPU 使用：任何空闲的 GPU 都可用（2026-10-16 用户指令）**：本集群上的**所有 GPU**
    都在可用范围内——只要某张卡当前是**空闲**的，agent 就可以用它跑本仓库的训练/评测，

      可以使用。**已经在跑别人作业的卡不要抢占**（显存/利用率明显>0 的卡跳过）。
    - **显存余量**：起活前仍需留出目标作业本身的显存，不得把别人的作业挤爆；
