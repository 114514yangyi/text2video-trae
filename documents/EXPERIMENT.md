# EXPERIMENT — 实验结果台账（experiment ledger）

> **用途**：把"每一次实验**实际测出了什么**"集中成可检索的表。一行 = 一个实验（一个 run 在
> 一个协议下的一次评测），字段包含：实验名称、来源 idea / 任务、做法、对照、协议、指标、
> 裁决、去向、备注。
> **与四态流转的关系**：`THINK.md` 管"想法还没试"、`TODO.md` 管"要做的事"、`FINISH.md` 管
> "做完了等裁决"、`NOTES.md` / `FAIL.md` 管"裁决结论"。本文件**不参与**这条流转，它是
> **横切台账**——同一件事的"指标与做法"在这里留一份按行可比的记录，四态文档继续管想法与结论。
> 换句话说：idea 的**命运**写在 THINK/FINISH/NOTES/FAIL，idea 的**实测数字**写在本文件。
> **建立**：2026-10-15 用户指令。规则正文见 `RULES.md` 知识库流转规范第 13 条，决策登记
> 见 `TODO.md` **D25**。

> **2026-10-27 FVD 实现切换注记（用户指令）**：自 2026-10-27 起，FVD 只由
> `video_metric.calculate_fvd` 原样计算产生（入口 `tools/eval_video_metric_fvd.py`，
> 规范 `FVD_SPEC.md`）。旧 SignViP 入口/旧脚本/旧约束，以及**历史 FVD 报告产物**
> （`reports/eval/**/fvd*.json`、`fvd*.npz`、`fvd_command.json`、`real_floor.json`、
> `fvd_ref/`）已按用户指令删除，因此本文件 2026-10-27 之前各行的「产物/报告」列可能
> 指向已删除文件。那些历史 FVD 数字（129.7493、142.3202、130.8486 等）**保留为历史记录**
> （台账行只增不删），但不再有证据文件可复算；因新旧实现的 FVD 核逐字节相同、协议不变，
> 数值等价的结论不变。新实验结果一律用新入口重算并写新的 `fvd.json`。

## 1. 这个文档解决什么问题

项目里已经有四类文档，但"某个方法当时测出多少"散落在 `NOTES.md` 的长段落、`FAIL.md` 的
失败链路、`reports/eval/` 的 JSON 目录名里。想知道"类似的三个臂各自多少分"要翻三种格式。

本文件把这些信息压成同一组列，使得：

- 横向比较：同类实验（都改文本侧、都改解码侧）的指标并排看；
- 追溯来源：这一行是从哪个 `idea-NNN` / TODO 条目 / 失败档案来的；
- 避免重复：动手前先搜本文件，看这条路线是不是已经测过、测出多少；
- 口径自证：协议列必须写全（侧、N、采样器、NFE、CFG、长度口径），否则数字不能比。

## 2. 什么时候写（写入时机）

这是本文件的**唯一硬性约定**，配合 `RULES.md` 第 13 条执行：

1. **实验跑完、指标落盘时立即登记一行**（状态列先写"待裁决"）。此时登记的是"跑过、数字在"，
   不要求已经知道好坏。
2. **该 idea 从 FINISH 出池时回填终值**——用户裁决后，把"结论 / 去向"两列补成
   `有效 → NOTES.md` 或 `无效 → FAIL.md`，并填上对应的 `FAIL-NNN` / NOTES 条目日期。
   **这就是"idea finish 以后内容进入本文件"的落地方式**：行在跑完时建，在出池时定稿。
3. **出池的行永不删除**。被证伪的路线保留原行（与 `FAIL.md` 不覆盖、不删除的规则一致）；
   若被新证据推翻，另起一行并在备注里注明取代关系。
4. **历史实验补登记**：2026-10-15 之前已经裁决的实验，按 `NOTES.md` / `FAIL.md` 已公布的数字
   补进本文件（本文件第 5、7 节首次建立时已补）。

## 3. 字段定义

| 字段 | 含义 | 填写要求 |
|------|------|----------|
| `exp-NNN` | 台账编号 | 只增不复用，与 `idea-NNN`、`FAIL-NNN` 平行 |
| 实验名称 | 人话名字 | 说明"改了什么"，例如"文本分支 lr 5e-5 续训 20k" |
| 来源 | 从哪来 | 必须写 `idea-NNN` 或 TODO 编号或 `FAIL-NNN`，便于向上追溯 |
| 做法 | 一句话机制 | 只讲改动本身；完整动机留给对应 idea 卡 |
| 变量 / 对照 | 变的是什么、和谁比 | 等预算 / 等参数量 / 只变一个超参。对照写错会让结论失效 |
| 协议 | 数据与采样口径 | 侧（默认 test；旧行可能有 train 采样）、N、采样器与 NFE、CFG、长度口径、回译链路 |
| 指标 | 实测数字 | **完整数字在第 5 节自动生成区**，本表只留最关键的一两个 |
| 结论 / 裁决 | 怎么样了 | 有效 / 无效 / 待测试 / 进行中；写"显著/不显著"要注明配对检验 |
| 去向 | 出池去哪 | `NOTES.md`（含日期）、`FAIL.md`（含编号）、或"待裁决" |
| 日期 | 登记与裁决日期 | 两次日期都可写，例如 `10-15 登记 / 10-15 裁决` |

**口径铁律（沿用 `RULES.md` 第 5、6 条）**：

- 当前规范（2026-10-21 建立，2026-10-27 实现切换）：此后所有实验的**唯一主对比指标 = 官方 FVD**
  （`FVD (I3D-K400 logits, first24 连续 24 帧, 224²)`，口径与实现见 `FVD_SPEC.md`）；任何对比
  **只在 test（固定 640 有效清单）上**报告，同采样器 / CFG / 长度口径 / FVD 口径 / 种子。
  **回译不再要求、不再作为对比/晋级指标**。**train 采样不是必需口径**；旧 train 侧数字只作过拟合诊断。
- **旧 FVD 口径作废**：`FVD (R(2+1)D-18 avgpool, 512-d)` 的 22–26 与 N=32 的 51.6–58.4
  不是官方 FVD，不得再与新数字并列或用于任何结论。
- **MRR 不能跨 N 比**：随机水平约 `(ln N + 0.577)/N`，N=642 时地板 = 0.0110。表里的 MRR 一律
  注明是地板的几倍。
- **FVD 不能跨 N 比**：同一个生成在 N=642 与 N=32 上能差一倍以上。
- **回译口径（历史）**：若个别分析仍要看回译，只用 SignMbart；历史 GFSLT 数字只能出现在
  第 7 节的"历史口径"里，禁止混入第 5 节。回译已退出主指标。
