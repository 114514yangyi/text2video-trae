## Actionable findings

1. **P2 — Motion-loss weighting depends on microbatch grouping.** Location: `t2v/train.py:192–196`; underlying reduction: `t2v/models/dynamic_loss.py:51–57`. `MultiScaleDeltaLoss` sums errors and valid temporal pairs over the whole microbatch, whereas the trainer averages microbatch losses equally through accumulation. For two unequal-length videos with per-video errors 1 and 9, microbatch size 1 weights them equally; microbatch size 2 weights the longer video's error more heavily. This changes the E4/E9 objective when microbatch size or its partition changes, even with the same effective batch. Scales absent from a short video's microbatch can also alter the scale average. Reduce each video's valid-pair error independently at each configured scale, use a defined zero contribution for unavailable scales, then average videos and accumulate. Add a variable-length, motion-enabled gradient-equivalence test. Existing linear-MSE accumulation coverage does not exercise this reduction.

2. **P2 — E10 resume unnecessarily requires its initialization checkpoint.** Location: `t2v/train.py:115` and `t2v/train.py:126–130`; construction at `t2v/train.py:45` calls `t2v/models/factory.py`, which reloads `initialization.pretrained_path`. The run's complete saved weights are only restored afterward. Thus a valid E10 `last.pt` cannot resume after the original PixArt initialization file is moved or unavailable, although that file no longer contributes any weights. Skip pretrained initialization when constructing a resumed system, retain the saved loaded/skipped-key audit metadata, and strictly restore the saved modules. Test resume after removing the original initialization file.
